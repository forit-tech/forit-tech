# Методология GitHub-аналитики

Карточка в профильном README строится автоматически по **публичным не-fork репозиториям** аккаунта `forit-tech`. Приватные репозитории намеренно исключены: их названия, языки, активность и любые производные метрики не попадают в публичный snapshot.

## Источники данных

Используется GitHub REST API через стандартный `GITHUB_TOKEN` workflow:

- список публичных репозиториев пользователя;
- распределение языков по байтам кода для каждого репозитория;
- коммиты автора `forit-tech` за последние 365 дней;
- публичные metadata репозиториев: название, description и topics.

## Метрики

### Публичные репозитории

Количество публичных не-fork репозиториев на момент запуска.

### Доля проектов Data / ML / AI

Репозитории относятся к одной из категорий: `Data Science`, `Machine Learning`, `AI / LLM`, `Data Engineering`, `Backend / Product`, `Другое`.

Для верхнего KPI считаются первые четыре категории:

`(Data Science + Machine Learning + AI / LLM + Data Engineering) / все анализируемые репозитории × 100%`

Это показатель тематической структуры портфолио, а не оценка навыка.

### Направления проектов

Используется детерминированный rule-based классификатор по названию, description, topics и языкам репозитория. Для каждой категории считается число совпавших признаков. Побеждает категория с максимальным score; при равенстве используется фиксированный приоритет правил.

Категории:

- Data Science;
- Machine Learning;
- AI / LLM;
- Data Engineering;
- Backend / Product;
- Другое.

Классификация эвристическая и может быть скорректирована вручную в будущем, если metadata репозитория недостаточно однозначны.

### Технологии

GitHub Linguist возвращает объём языков в байтах. Доля языка рассчитывается как его байты относительно суммарного объёма по всем анализируемым публичным репозиториям.

`число технологий` — количество языков с ненулевым объёмом, найденных GitHub Linguist. Это не количество фреймворков и не оценка сложности проекта.

### Индекс разнообразия

Используется нормированная энтропия Шеннона распределения языков:

`I = 100 × H(p) / ln(k)`

где `H(p) = -Σ p_i ln(p_i)`, `p_i` — доля языка по байтам, `k` — число языков с ненулевой долей.

`0` означает фактически один язык; значения ближе к `100` означают более равномерное распределение публичного кода между несколькими языками. Это **не рейтинг навыков**, seniority или качество кода.

### Активность за 12 месяцев

Для каждого месяца рассчитывается число найденных коммитов автора `forit-tech` в анализируемых публичных репозиториях за последние 365 дней. График нормируется относительно самого активного месяца только для визуального отображения.

Количество коммитов не используется как оценка продуктивности или качества работы.

### Темп за 90 дней

Сравнивается число коммитов за последние 90 дней с предыдущими 90 днями:

`(current_90d - previous_90d) / previous_90d × 100%`

Если в предыдущем окне не было коммитов, показатель выводится как `—`, чтобы не создавать бесконечный процент роста.

### Ритм работы

Каждый найденный commit timestamp переводится в `Europe/Moscow` и попадает в матрицу `7 × 8`:

- 7 строк — дни недели;
- 8 колонок — трёхчасовые интервалы `00`, `03`, `06`, `09`, `12`, `15`, `18`, `21`.

Интенсивность клетки определяется числом коммитов относительно максимальной клетки матрицы. Heatmap отражает только публичные коммиты, найденные GitHub API, и не является точным учётом рабочего времени.

### Самое активное время

Трёхчасовой интервал с максимальным числом публичных коммитов за последние 365 дней после перевода в `Europe/Moscow`.

### Основное направление

Категория с наибольшим числом классифицированных публичных репозиториев. При равенстве используется фиксированный порядок категорий, чтобы результат был воспроизводимым.

## Воспроизводимость и приватность

Каждый запуск сохраняет `analytics/snapshots/latest.json` с рассчитанными значениями и перегенерирует `assets/analytics.svg`. Workflow выполняется ежедневно и может быть запущен вручную.

В snapshot не сохраняются названия приватных репозиториев, их языки, коммиты или иные сведения. Карточка предназначена для описания **публичного технического портфолио**, а не всей активности аккаунта.
