# Методология GitHub-аналитики

Карточка в профильном README строится автоматически по **публичным репозиториям** аккаунта `forit-tech`. Приватные репозитории намеренно исключены: их названия, языки, активность и любые производные метрики не попадают в публичный snapshot.

## Источники данных

Используется GitHub REST API через стандартный `GITHUB_TOKEN` workflow:

- список публичных репозиториев пользователя;
- распределение языков по байтам кода для каждого репозитория;
- коммиты автора `forit-tech` за последние 365 дней;
- публичные metadata репозиториев: название, description и topics.

## Метрики

### Публичные репозитории

Количество не-fork репозиториев, доступных публично на момент запуска.

### Коммиты за 12 месяцев

Количество коммитов автора `forit-tech`, найденных в анализируемых публичных репозиториях за последние 365 дней. Это **не** полное число GitHub contributions: сюда не входят приватные contributions и активность, которую API не сопоставил с данным автором.

### Направления проектов

Репозитории классифицируются детерминированным rule-based классификатором по названию, description, topics и используемым языкам. Категории:

- Data Science / ML / AI;
- Data Engineering;
- Backend;
- Frontend / Product;
- Другое.

Это эвристическая классификация, а не ML-модель. При пересечении тематик побеждает категория с наибольшим числом совпавших признаков.

### Доля Data Science / ML / AI

`число репозиториев категории Data Science / ML / AI / число анализируемых репозиториев × 100%`

### Технологии по объёму кода

GitHub Linguist возвращает объём языков в байтах. Доля языка рассчитывается как его байты относительно суммарного объёма по всем анализируемым публичным репозиториям. Это не оценка сложности и не число написанных вручную строк.

### Индекс разнообразия технологий

Используется нормированная энтропия Шеннона распределения языков:

`I = 100 × H(p) / ln(k)`

где `H(p) = -Σ p_i ln(p_i)`, `p_i` — доля языка по байтам, `k` — число языков с ненулевой долей.

Интерпретация: `0` означает фактически один язык; значения ближе к `100` означают более равномерное распределение кода между несколькими языками. Это **не рейтинг навыков** и не оценка seniority.

### Темп за 90 дней

Сравнивается число коммитов за последние 90 дней с предыдущими 90 днями:

`(current_90d - previous_90d) / previous_90d × 100%`

Если в предыдущем окне не было коммитов, показатель выводится как `—`, чтобы не создавать бесконечный процент роста.

### Самый активный день

День недели с максимальным числом найденных коммитов за последние 365 дней. Временная база API — UTC.

## Воспроизводимость

Каждый запуск сохраняет `analytics/snapshots/latest.json` с рассчитанными значениями и перегенерирует `assets/analytics.svg`. Workflow выполняется ежедневно и может быть запущен вручную.
